FAQ Gap Analyser

FOREO · Sep – Nov 2026
role
AI Workflow Engineer Intern
stack
Python, Qwen via Ollama, Pydantic, HDBSCAN, scikit-learn, SQLite / SQLAlchemy, pytest, GitHub Actions
internal project · no public code

FOREO publishes FAQs for its products. Customers still ask questions on marketplaces. I'm building a tool that measures how much of what customers actually ask is answered by those FAQs, and where the biggest gaps are.

What I did

  • Collected 2,584 real marketplace questions in Turkish and English across 93 products, and matched them against the published FAQs.
  • Embedded the questions with a multilingual model and clustered them into 16 topics with HDBSCAN, so gaps show up as themes instead of thousands of single questions.
  • Used a local LLM (Qwen through Ollama, with Pydantic-validated output) as a judge: does this FAQ actually answer this question? Its verdicts agreed with my human labels 86.7% of the time on held-out data.
  • Result so far: the FAQs answer about 40% of questions. 8 of the 10 biggest gaps the tool flagged held up under manual review.
  • Split evaluation into synthetic and real hold-out sets, with a provenance rule that keeps synthetic data out of any number that reaches the business.

Revenue Manager Agent

2026 · OTEL build challenge
stack
Python, LangChain Deep Agents, Claude API, PostgreSQL (Neon), Playwright, Chainlit, LangSmith, Render
tests
50, across ETL, tools, skills and agent wiring
code ↗

An AI revenue manager for a fictional hotel, the Grand Harbour. You ask it things a hotel revenue manager would ask ("what's on the books for March?", "are we too dependent on one channel?") and it answers from the reservation database, showing which tools and skills it used.

What I did

  • Wrote 7 SQL-backed tools, including get_otb_summary, get_pickup_delta, get_as_of_otb and get_segment_mix, plus 2 subagents and 11 skill files covering pickup and pace, cancellation patterns, rate integrity, channel dependency and concentration risk.
  • Put a human-in-the-loop approval step in front of sensitive queries.
  • Built the ETL pipeline that feeds the agent. Extract: Playwright drives a real browser through the client-rendered reservation site (list pages, reference tables and each reservation's detail page), reading detail values straight from the live DOM with page.evaluate(). Transform: rows are cleaned and expanded to one row per reservation per stay night, keyed on stay date. Load: a truncate-and-reload into Neon Postgres, which is simpler and safer than upserts for a dataset that regenerates daily.
  • Made each load verifiable: the run records its anchor date in a scrape manifest and a SHA-256 fingerprint of the sorted rows, and the deployed app's /health endpoint returns the same fingerprint so I can check the live database matches. Postgres views apply the cancellation and provisional-booking filters once, so no tool can forget them.
  • Found with LangSmith tracing that one shared thread was growing from 24k to 226k tokens of context. Moving to per-session threads cut latency 58% (57.5s → 24.1s).
  • Replaced vague routing prompts with a deterministic routing table, which cut LLM calls on one-tool questions. Fixed a race condition with a per-session lock, and a bug where approval fired twice.

Spring Introspection MCP Server

2026 · Java
stack
Java 21, Spring Boot 4, Spring AI 2, Model Context Protocol, JUnit 5, AssertJ
tests
79 end-to-end against a live app, 17 redaction cases
code ↗

AI coding agents read source files. In Spring, a lot of what matters only exists at runtime: which property value won, why a bean was or wasn't created, whether a bean is really a proxy. This starter lets an agent ask the running app directly.

What I did

  • Wrote a Spring Boot starter that adds 7 MCP tools to any app: list_beans, describe_bean, why_bean, resolve_property, list_property_keys, explain_endpoint and describe_proxy.
  • resolve_property walks the whole precedence chain, so the agent sees that an env var overrode application.yml. why_bean reads the auto-configuration condition report.
  • describe_proxy shows a bean's real runtime class and the advisors applied to it, which surfaces problems like the self-invocation issue where @Transactional silently doesn't apply.
  • Built a deny-over-allow redaction layer so passwords, tokens and other secrets never reach the agent.
  • Benchmarked it against a naive agent that reads source and Actuator output: token use fell 88%, from 80.7K to 9.5K per question.

Modulation Classification with Graph Neural Networks

2025 · M.Sc. thesis, Trinity
stack
Python, PyTorch, PyTorch Geometric, scikit-learn, PyWavelets
supervisor
Dr. Viet Quoc Pham
data
RadioML 2018.01A, 24 modulation classes
final code ↗earlier version ↗

Given a short burst of raw radio samples, work out how it was modulated. It's a core step in spectrum monitoring and cognitive radio, and it gets hard at low signal-to-noise ratios where the constellations blur together.

What I did

  • Turned each 1024-sample I/Q frame into a graph: 15 overlapping 128-sample segments become nodes, connected in a chain. The GNN uses GATv2 or TransformerConv layers with SAG pooling.
  • Fed the model three views of the same signal: time-domain segments, an STFT spectrogram and a wavelet (CWT) view, with a wavelet denoising step in front.
  • Added SNR-aware expert adapters, since the model behaves very differently above and below about 5 dB.
  • Tried ArcFace and CosFace metric-learning heads, and higher-order cumulant features (C20 to C42) as a classical baseline.
  • Extracted the network's embeddings, trained a calibrated SVM on them, and fused the two with SNR-dependent weights.
  • Used phase rotation, time shift, noise, mixup and SpecAugment for augmentation.

Activity Recognition from Phone and Watch Sensors

2025 · ML
stack
Python, LightGBM, scikit-learn, NumPy, ONNX
result
92.25% test accuracy on 25,452 windows
code ↗

Classifies what someone is doing (biking, sitting, standing, walking, going up or down stairs) from smartphone and smartwatch accelerometer and gyroscope data, using the Heterogeneity HAR dataset.

What I did

  • Merged accelerometer and gyroscope streams on timestamp and label, then cut them into 200-sample windows (about 4 seconds) with 50% overlap.
  • Extracted 42 time and frequency features per window: mean, standard deviation, median, IQR, zero-crossing rate and FFT moments.
  • Chose a feature-based LightGBM model over deep learning to keep it small, fast and easy to debug, and tuned it with RandomizedSearchCV.
  • Exported the model to ONNX for deployment. Stairs up versus stairs down is still the hardest pair to separate.

Depression and Voting Patterns

2025 · spatial statistics, Trinity
stack
R, sf, GAMs, US Census shapefiles
scale
3,073 counties, 50 states
coursework · no public repo

Do counties with higher depression rates vote more Republican? A simple model says yes, strongly. Most of that turns out to be geography.

What I did

  • Joined election, health and census data for 3,073 counties, and matched each county to its map position using Census shapefiles in R with sf.
  • The simple model said each 1-point rise in depression raised the odds of a Republican vote by about 17%.
  • Built 6 progressively stronger spatial models (GAMs) controlling for location, state and race. The effect shrank to about 2%: smaller, but still significant.
